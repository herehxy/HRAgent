# HRAgent 打包与热更新方案（v2.2.0）

> 目标：**重装/升级程序，一个字节都不动用户的数据与配置**；新功能要的数据
> （如头像）能自动补齐；既能给"免安装绿色包"，也能给"安装包"，还能热更新。

---

## 一、结论先行：靠"物理隔离"而不是"靠自觉"

```
安装目录（可随时删、随时换）          用户目录（永不触碰）
┌────────────────────────────┐      ┌──────────────────────────────┐
│ HRAgent工作台.exe          │      │ %LOCALAPPDATA%\HRAgentData\  │
│ _internal\                 │      │   ├─ data\                  │
│   ├─ *.pyd / base_library  │      │   │   ├─ workbench.db（主库） │
│   ├─ config\  ← 配置**模板**│      │   │   ├─ archive\（简历原件） │
│   └─ seed\data\ ← 演示种子 │      │   │   ├─ avatars\（证件照）   │
│ HRAgent安装器.exe          │      │   │   └─ master.key（PII 密钥）│
│ HRAgent更新器.exe          │      │   └─ config\ ← **你的**配置  │
│ 使用说明.txt               │      │       ├─ model.json（模型）   │
└────────────────────────────┘      │       ├─ secrets.json（API Key）│
                                    │       ├─ mailbox.json（邮箱） │
      ↑ 更新 = 只换左边这一坨        │       └─ tiers.json（档位阈值）│
      ↑ 永远不会写右边               └──────────────────────────────┘
```

**为什么这样就自动安全**：程序启动时（`repo_src/webapp_launcher.py`）把
`TP_USER_HOME` 指到 `%LOCALAPPDATA%\HRAgentData`，于是 `app/paths.py` 里的
`DATA_DIR` / `CONFIG_DIR` 全部落在安装目录之外。更新器只写安装目录 →
**没有任何一条代码路径能碰到用户数据**。这不是"我们记得不覆盖"，是结构上做不到。

## 二、现状核实（都已逐条验证，不是推断）

| # | 事实 | 证据 |
|---|---|---|
| 1 | 用户数据在安装目录外 | `webapp_launcher.py` 设 `TP_USER_HOME/TP_CONFIG_DIR/TP_DATA_DIR`；`paths.py` 认这些变量 |
| 2 | 旧版数据会自动迁移且**拒绝覆盖** | `profile_migrate.migrate_profile`：目标已有 `workbench.db` → 直接 `FileExistsError`；迁移前后做行数快照比对 + `master.key` sha256 比对 |
| 3 | 配置播种**只补不缺** | `profile_migrate.seed_config`：不覆盖已有配置与任何密钥；JSON 按 key 递归合并，用户值（含空串）优先 |
| 4 | 新功能加数据 = 幂等加列 | `db._ensure_columns` → `ALTER TABLE … ADD COLUMN`，老行不写值、保持 NULL |
| 5 | 头像已按此实现 | `app/avatar.py` + `candidates.avatar_path`（三态）+ `/api/candidates/{id}/avatar` |
| 6 | 图标沿用定稿版 | `app.ico`(256×256) / `icon_tray.png`，9/30 定稿，主程序与新工具都用 |

## 三、新功能的数据怎么落（以头像为例）

头像这类"新功能带新数据"，落地只有三条规则，**全部满足就不会覆盖老数据**：

### 规则 1：列用幂等加列，不重建表
```python
# repo_src/app/db.py → _ensure_columns()
"candidates": {
    "avatar_path": "TEXT",   # 幂等：已有列就跳过，老行保持 NULL
}
```
`CREATE TABLE IF NOT EXISTS` 不会给已存在的表加列，所以**必须**显式
`ALTER TABLE ADD COLUMN`；这一步放在 `db.connect()` 的初始化里，每次启动都会跑，
老库第一次用新版就自动补齐。

### 规则 2：列用"三态"，不新增状态表
| 值 | 含义 |
|---|---|
| `NULL` | 还没试过（首次渲染时懒抽一次） |
| `"-"` | 试过了，没有可用照片（不再重试） |
| `"data/avatars/12.jpg"` | 有图 |

为什么不用布尔位：抽错照片是真实风险（抽到 logo、架构图、整页缩略图），
所以要能表达"试过且失败"这个中间态。三态让"重抽/去掉"这两个动作都有落点。

### 规则 3：文件落 DATA_DIR，路径存相对路径
- 头像文件 → `%LOCALAPPDATA%\HRAgentData\data\avatars\`
- 库里存**相对路径**（`data/avatars/12.jpg`），由
  `paths.resolve_data_path()` 在运行时解析成当前数据目录下的绝对路径。
- 为什么存相对而不是绝对：数据目录可以被整体挪走（`TP_DATA_DIR`），
  存绝对路径会全部失效；迁移时 `rewrite_db_paths()` 还能把旧根批量改写成新根。

> 推广到任何新功能：**要加数据就加列/加表（幂等），文件就落 DATA_DIR，
> 路径存相对**。三条都满足，"升级不覆盖老数据"就是自动成立的。

## 四、热更新：只换功能

### 4.1 更新包里有什么
`HRAgent更新包-<旧>-to-<新>.zip`：
```
update.json          版本、逐文件 sha256、待删除文件清单
HRAgent工作台.exe     新版主程序（业务代码打包在 exe 的 PYZ 里，所以换 exe 是主力）
_internal/...        新版运行时文件（依赖、模型文件）
```
**构建期就排除**（`tools/build_release_v2.py`）：任何路径段含 `data`
（`seed/` 除外）、任何 `*.db / *.key / *.secret / *.sqlite` 一旦出现在差异里
→ **直接中止构建**，不是静默跳过。静默跳过会让人以为"更新了"，
实际某个关键文件没换（这项目反复踩的"假通过"）。

### 4.2 更新器执行流程（`tools/hra_updater.py`）
1. 检查程序是否在跑（在跑就拒绝，提示先在托盘「退出」）
2. 读 `update.json`，**校验包内每个文件的 sha256**（先验再写，别写到一半发现包坏了）
3. 备份所有将被覆盖的文件 → `<安装目录>\_update_backup\<时间戳>\`
4. 写新文件（先写 `.hra_tmp` 再 `os.replace` 原子替换）
5. 写 `version.json`（版本 + 更新时间）
6. **数据快照比对**：更新前后各给用户数据目录做一次快照
   （文件清单 + 大小 + mtime + 库文件 sha256），不一致 → 立即回滚并报错

### 4.3 三道安全网
| 道 | 拦什么 | 触发后的动作 |
|---|---|---|
| 1. 路径白名单 | 清单里出现用户数据目录 / `data/` / 密钥类文件 | 拒绝更新并说明原因 |
| 2. 写前备份 | 写入中途失败（磁盘满、权限、文件被占用） | 自动回滚到备份 |
| 3. 数据快照比对 | 不知为何动了用户数据 | 自动回滚 + 报出具体变动文件 |

### 4.4 回滚
`<安装目录>\_update_backup\<时间戳>\` 里是被替换的旧文件，
手工拷回去即可；更新器出错时也会自动拷回。

## 五、安装包

没有 Inno/NSIS 可用（机器上都没装），所以安装器自己写（`tools/hra_installer.py`，
PyInstaller 打成 `HRAgent安装器.exe`）：

| 能力 | 做法 |
|---|---|
| 选安装目录 | 默认 `%LOCALAPPDATA%\Programs\HRAgent工作台` |
| 覆盖升级 | 目标已存在 → 先整体备份到 `<目录>.bak_<时间戳>`，再覆盖 |
| 快捷方式 | 桌面 + 开始菜单（用 PowerShell + 环境变量建 .lnk，规避中文路径引号/编码问题） |
| 卸载 | 写 HKCU 卸载项（控制面板→程序和功能 可卸载）；`--uninstall` 只删程序，**数据默认保留** |
| 删数据 | 必须显式 `--purge-data`，且是独立动作 |
| 数据安全 | 安装前后对 `%LOCALAPPDATA%\HRAgentData` 做快照比对，日志里明确写"用户数据未被触碰" |

**分发形态**
```
HRAgent安装器.exe                    ← 双击，选目录，安装
HRAgent程序包-v2.2.0.zip             ← 程序本体（安装器自动找旁边的它）
HRAgent工作台-Windows版-v2.2.0.zip   ← 免安装版，解压即用
HRAgent更新包-v2.1.0-to-v2.2.0.zip   ← 增量更新包（只含变化文件）
```

## 六、目录职责表（改代码前先看这张）

| 路径 | 是什么 | 升级时 | 卸载时 |
|---|---|---|---|
| `<安装目录>\HRAgent工作台.exe` | 主程序 | **替换** | 删 |
| `<安装目录>\_internal\config\` | 配置**模板** | **替换**（用户值在外置目录，不受影响） | 删 |
| `<安装目录>\_internal\seed\data\` | 演示数据种子 | 替换 | 删 |
| `<安装目录>\_update_backup\` | 旧文件备份 | 保留 | 删 |
| `%LOCALAPPDATA%\HRAgentData\data\` | **用户的库/简历/头像** | **绝不碰** | **保留** |
| `%LOCALAPPDATA%\HRAgentData\config\` | **用户的配置与密钥** | **绝不碰** | **保留** |

首次运行的种子迁移：安装目录的 `seed/` 被 `candidate_legacy_roots()` 识别为一个
legacy 根 → `migrate_profile()` 复制到用户目录（行数快照 + 主密钥 sha256 双重校验），
随后 `seed_config()` 把配置模板补进用户配置目录（只补缺失键）。

## 七、验收口径（怎么证明"没覆盖数据"）

不靠"我觉得没覆盖"，靠可复现的检查：

1. **快照法**：更新前后对用户数据目录做全量快照（清单/大小/mtime/sha256），
   逐项比对 —— 由更新器自己执行并写进日志。
2. **安装器自证**：安装前后同样快照比对，日志输出"用户数据未被触碰（N 个文件）"。
3. **端到端演练**：模拟 安装 → 首次运行（生成用户档案）→ 造一条数据 →
   热更新 → 检查数据行数/头像列/配置文件内容**逐项未变**。
4. **加列幂等**：老库（无 `avatar_path` 列）启动新版后，列被补上、
   老行 `avatar_path` 仍为 NULL（**不写值、不改老数据**）。

## 八、常见故障与处置

| 现象 | 原因 | 处置 |
|---|---|---|
| 更新器说"程序还在运行" | 托盘没退、只关了浏览器窗口 | 托盘图标右键「退出」后重试 |
| 日志出现 `fallback model metadata` / `Unknown model` | `models.json` 没被加载 | 重新跑一次完整安装（不是更新） |
| 界面还是旧的 | 浏览器缓存了内联 JS | 响应已带 `Cache-Control: no-store`；强制刷新一次 |
| 更新后行为异常 | 新旧数据模型不兼容 | 用 `_update_backup\<时间戳>\` 回滚；再报问题 |
| 数据"不见了" | 看的是安装目录里的旧库 | 真实数据在 `%LOCALAPPDATA%\HRAgentData\data\workbench.db` |
