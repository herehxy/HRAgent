# 智能助手能力扩展 · 技术方案（v6.6.0）

> 日期：2026-11-25
> 目标：让 27B 级别的小参数模型在人才库工作台里“能做、做对、做完”，
> 不靠模型自由发挥，而靠**工具边界 + 确定性路由 + 固定 SOP + 可复述结果**。
> 红线不变：写操作仍只生成待确认提案；对外发信、物理删除仍不开放。

---

## 一、问题：不是模型不会，是能力没交到它手上

截图里的真实链路：

```
HR：导入邮箱最新简历
  → route_tools() 命中 mail 组（“邮箱”）
  → mail 组里没有 ingest_resumes
  → 模型只看到 list_source_files
  → 扫了本地待导入目录，回答“目录为空”
```

这不是模型能力问题，是**路由把真正的执行工具藏掉了**。同类问题还有：

| 现象 | 根因 |
|---|---|
| “导入邮箱简历”只得到目录扫描结果 | `ingest_resumes` 只在 admin 组；mail 为主组时不可见 |
| 问“这个人投了几次、是否同一份”答不全 | `get_candidate` 没返回 `submissions`（档案详情里有，工具层没带） |
| 界面上能按第一学历/四六级/海外/面试单位筛，助手查不到 | `search_candidates` 没暴露这些 `db.list_candidates` 已有参数 |
| 助手说“系统不支持直接抓取” | 规则降级路径残留旧口径，与真实工具能力矛盾 |
| 能查但不能解释“为什么没导入” | 没有导入诊断工具，模型只能猜 |
| 问“今天先做什么”要绕多步 | 没有直接读取今日待办的只读工具 |
| 问“你能做什么”容易编限制 | 没有能力清单工具，模型凭印象回答 |

## 二、设计原则（面向 27B）

1. **工具就是能力边界**
   能做的事必须有工具；没有工具才说限制。严禁模型凭印象判断“做不到”。

2. **确定性优先**
   能用 SQL / 规则算清楚的（人数、分布、重复、超大、导入结果），
   一律服务端算好，模型只负责复述，不让它心算。

3. **少而强**
   高频任务给“组合工具”（一次调用完成一件事），而不是让 27B 串联五六个原子工具。

4. **路由必须覆盖主意图**
   主组里必须同时有“查”和“做”的工具；次组至少补只读/计算工具。
   路由错一次，27B 就会用错误的工具给出看似合理的错答案。

5. **结果可复述**
   每个新工具都返回 `summary` / `counts` / `next_actions`；
   模型先读摘要，需要细节再读明细，避免长 JSON 把 32k 窗口挤爆。

6. **只读下一步不问**
   “要不要我帮你查一下历史/状态”这类只读动作，直接查完再汇报；
   只有写操作或需要 HR 决策时才征求确认。

## 三、能力矩阵

| HR 想做的事 | 工具 | 说明 |
|---|---|---|
| 收邮箱 / 导文件夹 | `ingest_resumes`（增强） | 真执行；返回新增/重复/超大/失败/新候选人 |
| 为什么没导入 | `import_diagnostics`（新增） | 邮箱配置、密钥、目录、最近错误、导入历史逐项体检 |
| 今天先做什么 | `daily_brief`（新增） | 直接读今日待办与优先级，不额外调模型 |
| 你能做什么 | `assistant_capabilities`（新增） | 权威能力清单 + 明确限制 |
| 按学校/专业/四六级/第一学历/海外/面试单位/结论筛人 | `search_candidates`（扩展） | 与界面、导出同一套 `db.list_candidates` 口径 |
| 看某人投了几次、是否同一份 | `get_candidate`（扩展） | 返回 `submissions` 时间线与重复标记 |
| 按条件导出名单 | `export_roster`（扩展） | 与检索筛选对齐，避免“筛得到、导不出” |
| 打包简历 | `export_resume_bundle`（扩展） | 同上 |
| 看岗位要求/进展 | `job_detail`（新增） | 完整 JD、门槛、阶段分布、最近投递 |
| 看归档的人 | `search_candidates(archived=true)` | 归档页能力补进助手 |
| 复杂多步任务 | 现有 7 条 SOP + 新增 3 条 | 导入、今日待办、能力说明 |

## 四、工具设计

### 4.1 `ingest_resumes` v2（真执行 + 可复述）

参数：

```json
{
  "source": "auto | mailbox | folder",
  "folder": "可选，source=folder 时的目录",
  "limit": "邮箱最多处理多少封，0=全部（默认 0）",
  "diagnose_if_empty": "默认 true；结果为 0 时自动附带诊断"
}
```

返回：

```json
{
  "ok": true,
  "source": "mailbox",
  "summary": "邮箱收取完成：新邮件 3 封，新增候选人 2 人，同人新版本 1 份，重复跳过 2 份。",
  "counts": {"mails": 3, "added": 2, "merged_versions": 1, "skipped_dup": 2, "failed": 0},
  "new_candidates": [{"candidate_id": 12, "name": "张三", "file": "张三.pdf", "status": "added", "tier": "B"}],
  "skipped": [{"file": "李四.pdf", "reason": "同一份简历已入库（SHA256 相同）"}],
  "failures": [],
  "diagnosis": {"verdict": "...", "checks": []},
  "next_actions": ["新人默认在「待指定」；需要归岗可以说『把刚收的人归到工艺技术岗』"]
}
```

要点：

- `auto`：邮箱模式为 imap/eml 且配置完整 → 邮箱；否则 → 文件夹。
- 邮箱模式为 off 时明确告知，并给“改用文件夹”的替代，不静默扫 0。
- 汇报口径固定：**新增 / 同人新版本 / 重复跳过 / 超大 / 失败**分开说。
- 返回里带 `new_candidates` 姓名，模型不需要再查一遍。

### 4.2 `import_diagnostics`（只读体检）

一次返回：

- 邮箱：模式、服务器、账号、密钥是否存在（不返回密钥）、最近 5 封邮件及错误；
- 文件夹：路径、待导入文件数、超大文件数；
- 历史：最近 N 天导入/重复/超大记录按动作计数；
- `checks`：逐项 `{key, ok, detail, fix}`；
- `verdict`：一句人话结论；
- `next_actions`：模型可以直接照着说/做。

判定顺序：

```
模式关闭 → 账号/服务器缺失 → 密钥缺失 → 文件夹为空 →
超大文件 → 全部重复 → 最近邮件错误 → 配置正常/没有新邮件
```

### 4.3 `daily_brief`（只读）

直接复用 `app/agent/brief.build(use_llm=False)`，返回：
`headline / priorities / stats / total / source / note`。
不额外调一次模型，避免 27B 串行两轮。

### 4.4 `assistant_capabilities`（只读）

返回按域分组的能力清单（找人、流程、导入、邮件名单、数据系统）+
明确限制（不能代发邮件、不能物理删除、聊天附件不自动入库）+
每条 1 个例句。模型被问“你能做什么”时以它为准，不再凭印象编限制。

### 4.5 `search_candidates` 扩展

新增参数（全部下沉到 `db.list_candidates`，与界面/导出口径一致）：

```
school / major / strong / cet / overseas / bachelor /
date_from / date_to / interview_date / interview_unit /
outcome / pool_status / needs_review / archived
```

其中：

- `school`、`major` 是显式字段筛选，不走全文关键词，避免“校名同时出现在备注里”的误命中；
- `strong` 支持多个具体院校（并集）；
- `archived` 三态：`false`（默认）/ `true` / `all`；
- 返回 `count`（总命中）与 `returned`（实际返回），27B 不会把“返回 20 人”说成“只有 20 人”。

### 4.6 `get_candidate` 补 `submissions`

返回每次投递的时间、渠道、文件名、`document_id`、`duplicate` 标记。
支持回答“投了几次、几次是同一份、每次什么时候”。

### 4.7 `job_detail`（新增）

单个岗位的完整信息：部门、状态、学历/年限门槛、必需/加分技能、完整 JD、
已收投递数、各阶段人数、最近投递的候选人。解决“这个岗位要求是什么”
“某岗位进展怎么样”只能靠 `list_jobs` 摘要回答的问题。

### 4.8 邮箱 `limit` 口径修正

无进度条的助手/CLI 调用原来走 `mb.incoming()`，内部固定 `fetch_imap(limit=200)`，
助手传 `limit=0`（全部）也只收 200 封。现改为直接调用
`fetch_imap(cfg, cursor, limit)`，与界面「收邮件」的 `limit=0` 口径一致。

## 五、路由改造

新增 `import` 组，并把它补进 mail / admin：

```python
"import": ["ingest_resumes", "import_diagnostics", "list_source_files",
           "list_import_history", "mailbox_status"]
```

关键词：`导入 / 收取 / 抓取 / 同步 / 采集 / 收简历 / 收邮件 / 待导入 / 没导入 / 没收到简历`。

同时：

- `mail` 组加入 `ingest_resumes`、`import_diagnostics`、`list_source_files`；
- `admin` 组加入 `import_diagnostics`；
- `govern` 组加入 `daily_brief`；
- 新增 `help` 组（`assistant_capabilities`），关键词：`能做什么 / 会什么 / 有什么功能 / 怎么用 / 帮助`；
- 次组仍只补只读/计算工具，但主组必须自带执行工具。

**回归用例**：`route_tools("导入邮箱最新简历")` 必须包含 `ingest_resumes`；
即使历史消息把 mail 组顶到主组，mail 组里也必须有 `ingest_resumes`。

## 六、SOP（新增 3 条）

### `resume_import`

1. 直接调 `ingest_resumes(source=auto)`；HR 指定邮箱/文件夹就传对应 source。
2. 返回 0 或 error 时，调 `import_diagnostics` 解释原因，不用 `list_source_files` 代替导入。
3. 有新增：按 counts 汇报，列出新增姓名（最多 10 个），并给下一步。
4. 不反问“要不要帮你导入”，HR 已经说了要导入。

### `daily_brief`

1. 调 `daily_brief`；
2. 按 headline + priorities 汇报，带姓名；
3. 需要处理时，用对应写工具生成提案，不直接改库。

### `assistant_help`

1. 调 `assistant_capabilities`；
2. 按域分组回答，每组给 2–3 个例句；
3. 明确限制用工具返回的原话，不自行扩大限制。

## 七、提示词与 27B 适配

新增规则：

- 导入/收取/抓取简历 → 直接调 `ingest_resumes`，不要说“系统不支持对话触发”；
- 只读下一步直接做，不问“需要我帮您查看吗”；
- 导入结果必须用工具 counts，分项汇报；
- 被问能力 → 调 `assistant_capabilities`；
- 工具返回 `next_actions` 时优先照做；
- 聊天附件未入库 → 引导点附件上的「入库」，不要让助手调 `ingest_resumes` 处理聊天临时文件。

小参数模型（≤32B）额外注入一段执行纪律：

- 每轮 1–3 个必要工具，按 SOP 顺序；
- 先读 `summary/counts`，再读明细；
- 参数名/枚举/日期严格照工具说明；
- 不编造未返回的姓名/数字；
- 多步任务先列步骤再执行。

同时把 27B 的可见工具上限收紧到 18（窗口更小时由现有预算继续收紧）。

## 八、验收

1. `route_tools("导入邮箱最新简历")` 包含 `ingest_resumes`（单测）。
2. 离线规则模式说“导入简历”时不再回答“不能由对话触发”，而是执行导入或给出真实诊断。
3. `import_diagnostics` 能在以下场景给出不同 verdict：
   模式关闭 / 未配账号 / 缺密钥 / 文件夹空 / 文件超大 / 全部重复 / 正常无新邮件。
4. `search_candidates(school=...)` 与界面筛选结果一致；`count` 是总命中数。
5. `get_candidate` 返回 `submissions`，重复投递带 `duplicate=true`。
6. `daily_brief` 不调用模型也能返回 priorities。
7. `assistant_capabilities` 输出包含明确的“不能做”清单。
8. 现有测试全绿；新增测试覆盖以上 1–7。

---

## 九、不做的事

- 不开放助手直接发邮件（只能起草）。
- 不开放物理删除（只能归档/移入回收站）。
- 不让聊天附件自动入库（必须 HR 点「入库」）。
- 不为“能力增强”放宽写操作提案制。
- 不把长 JSON 原样塞给 27B；新工具结果都做摘要与条数上限。
