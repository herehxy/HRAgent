# 前端弹窗与输入框优化方案

> 范围：`repo_src/app/ui.py`（单文件前端，`_PAGE` 内联 HTML/CSS/JS）
> 设计前提：**保留既有配色体系**（`:root` 令牌不动），只改弹窗与输入框这两类组件的
> **边框、对比强度、结构、交互与无障碍**。基调是「弱框线、柔填充、靠明度分层」，
> 不引入强对比描边与高饱和强调。

---

## 一、现状审计

### 1.1 弹窗：16 处 `resultModal` + 6 处 `progressModal`，全部走同一个 `#modal`

| 规范项 | 现状 | 缺口 |
|---|---|---|
| 先做减法 | 16 处调用里，**4 处是纯成功/空态/字段校验** | 过度使用弹窗 |
| 模态 vs 非模态 | 全部模态；轻量确认靠 `confirm()` 原生框 | 缺 Popconfirm 层 |
| 结构 | 有标题、关闭按钮、遮罩 | 标题是「详情」「完成」「处理中」——**无信息量** |
| 标题/正文滚动 | `.sheet{overflow:auto}` 包住标题 | **滚动时标题跟着滚走** |
| 尺寸 | 单一 `max-width:920px` | 无分档；确认框也用 920px 太宽 |
| 窄屏 | `padding:22px` 兜底 | 无 bottom sheet 降级 |
| 无障碍 | **`role="dialog"` 0 个、无 `aria-modal`、无 `aria-labelledby`** | 全缺 |
| Esc | 无 | 全缺 |
| 焦点陷阱 | 无 | Tab 会跑到背景页 |
| 焦点归还 | 无 | 关闭后焦点丢到 `<body>` |
| 遮罩关闭 | `onclick` 无条件关闭 | **进度条弹窗点外面也会关**，但任务还在跑 → 用户以为取消了 |
| 视觉 | 遮罩 `rgba(29,33,41,.45)` 纯色；`.sheet` **无边框无阴影** | 靠遮罩硬对比「浮起」，观感生硬 |
| 动画 | 无 | 无入场过渡 |
| reduced-motion | 无 | 未尊重系统设置 |

### 1.2 输入框：一行全局规则包打所有

```css
input,select,textarea{padding:7px 12px;border:1px solid var(--line);
  border-radius:var(--r-ctl);font-size:14px;color:var(--ink);
  background:var(--surface);font-family:inherit}
button:focus-visible,select:focus-visible,input:focus-visible,...{
  outline:2px solid var(--focus);outline-offset:1px}
```

| 问题 | 说明 |
|---|---|
| 白底 + 1px 灰框 | 在白色卡片上等于「一个框」，边界靠描边硬撑，密集表单里框线互相打架 |
| focus 是 2px 深蓝硬边 | `#1d5fd6` 对白 5.74，视觉上非常抢；这是「强对比框线」的典型 |
| 无 hover 态 | 鼠标移上去毫无反馈 |
| 无 disabled 态 | 禁用输入框与可用输入框长得一样 |
| 无错误态 | 校验失败只能靠弹窗说，字段本身不标 |
| `select` 与 `input` 同高不同观感 | select 有原生箭头，填充底要单独处理 |

## 二、决策规则：什么时候不该用弹窗

**这是本方案的第一条，也是最重要的一条。** 弹窗是最后选项，不是默认选项。

```
需要用户看到 / 决策
├─ 不需要回应就能继续？
│   ├─ 是 → 不用弹窗
│   │   ├─ 纯结果反馈（成功/失败摘要） → Toast（3.5–5s 自动消失，可手动关）
│   │   ├─ 空态 / 无需操作（"没有需要重跑的人"） → Toast
│   │   └─ 字段级校验（"没有可上传的文件"） → 就地提示 / Toast
│   └─ 否 → 需要阻断
│       ├─ 轻量二选一（"删除这一条？"） → Popconfirm（贴着触发点，鼠标动线最短）
│       └─ 必须看完才能继续
│           ├─ 结果需要逐条核对（上传失败明细、导入报告） → 模态弹窗
│           ├─ 不可逆操作确认（发信、批量删除） → 模态弹窗（危险态 + 禁遮罩关闭）
│           └─ 长流程进度（导入/分析/收取，带百分比） → 模态弹窗（门控型）
└─ 多步骤 / 复杂表单（字段 > 8） → 独立页面或抽屉，不进弹窗
```

### 本轮据此调整的 4 处

| 位置 | 原状 | 改为 | 理由 |
|---|---|---|---|
| `uploadFiles` 无文件可传 | `resultModal(kind:'warn')` | `toast('...','warn')` | 字段级校验，无需阻断 |
| `rerunBatch` 全部完成 | `resultModal(kind:'ok')` | `toast('...','ok')` | 纯成功反馈 |
| `rerunBatch` 无需重跑 | `resultModal(kind:'info')` | `toast('...','info')` | 空态，不需要决策 |
| `runBatchAnalyze` 全部完成 | `resultModal(kind:'ok')` | `toast('...','ok')` | 纯成功反馈 |

**保留弹窗的**：上传完成（有失败明细要逐条看）、导入完成（报告要核对）、
分析部分失败（要看哪几个人失败）、进度条（门控型，必须等）。

## 三、弹窗规范

### 3.1 结构（三层，标题与底栏固定）

```
.modal            遮罩层：fixed inset:0，柔化 → 半透明 + 轻模糊
└─ .sheet         容器：flex column，overflow:hidden（**不是 auto**）
   ├─ .sheet-hd   头部：shrink-0（标题 + 头部按钮 + 关闭）
   ├─ .mbody      正文：flex:1，min-height:0，overflow-y:auto  ← 只有这里滚
   └─ .sheet-ft   底栏：shrink-0（动作按钮，确认在右取消在左）
```

**关键改动**：原 `.sheet{overflow:auto}` 把标题一起滚走。改为容器 `overflow:hidden`
+ 正文独立滚动，等价于 `flex-1 overflow-y-auto min-h-0` 的做法。

### 3.2 尺寸分档

| 档位 | 类名 | 宽度 | 用途 |
|---|---|---|---|
| 小 | `.sheet--sm` | 400px | 确认型、单行结果 |
| 中 | `.sheet--md` | 520px | 标准结果、进度条（**默认**） |
| 大 | `.sheet--lg` | 720px | 上传明细、导入报告 |
| 特 | `.sheet--xl` | 920px | 档案详情（唯一需要这么宽的） |

统一钳制：`max-width:min(<档位>, calc(100vw - 32px))`，`max-height:calc(88vh / var(--z))`。

> ⚠️ 高度必须写 `calc(... / var(--z))`，与 `:root` 的 `--z` 同步。
> body 有 zoom 时 `88vh` 拿到的是视觉像素，会高出整整一个 zoom 倍（已在 `.layout` 踩过）。

### 3.3 窄屏降级

`@media (max-width:600px)`：`.sheet` 变 bottom sheet

- `align-items:flex-end`（贴底）
- `border-radius:16px 16px 0 0`（只圆上面两角）
- `max-height:min(76vh / var(--z), 620px)`
- `width:100%`

### 3.4 关闭路径（按风险分级）

| 类型 | 显式关闭 | Esc | 点遮罩 |
|---|---|---|---|
| 解释型（详情） | ✓ | ✓ | ✓ |
| 确认型（结果/上传） | ✓ | ✓ | ✓ |
| **门控型（进度条）** | ✓（停止按钮） | ✗ | **✗** |
| **危险态（发信/删除）** | ✓ | ✓ | **✗** |

实现：`#modal` 上加 `data-lock="1"` 时，Esc 与遮罩点击都不生效。
当前进度弹窗点外面会关掉但任务还在跑 —— 这是真实的一致性缺陷。

### 3.5 无障碍（不可妥协）

| 项 | 实现 |
|---|---|
| 容器语义 | `role="dialog"` `aria-modal="true"` `aria-labelledby="mTitle"` |
| 关闭按钮 | `aria-label="关闭"` + `type="button"` |
| 打开时焦点 | 移到第一个可聚焦元素；无则聚焦容器（`tabindex="-1"`） |
| 焦点陷阱 | 拦截 `Tab` / `Shift+Tab`，在容器内首尾循环 |
| 焦点归还 | 关闭时 `focus()` 回打开前的 `document.activeElement` |
| 背景 inert | 关闭态给 `#app` 加 `inert`（现代浏览器同时屏蔽键盘与读屏） |
| 播报 | 容器 `aria-live="polite"`（结果类），进度用 `role="status"` |

> 为什么不用原生 `<dialog>`：本项目页面是**服务端拼字符串 + 单个 `#modal` 复用**的架构，
> 换成 `<dialog>` 要重写全部 22 处调用的复用逻辑（`mBody` 注入、`setModalTitle`、
> `afterClose` 接力、`chain` 原地切换）。收益是省掉焦点陷阱自研，
> 但改动面远大于风险。这里选择**自研并逐项覆盖**（焦点/Esc/遮罩/归还）。

### 3.6 视觉：弱框线，靠阴影浮起

**不采用**：`.sheet` 的 1px 实线边框、遮罩的深色硬对比。

```
遮罩：rgba(31,35,41,.28) + backdrop-filter:blur(2px)
      —— 比原来 .45 轻，靠模糊而不是靠深度隔离
容器：无边框，圆角 12px，阴影分两层
      0 1px 2px rgba(31,35,41,.04)   ← 贴边（质感）
      0 12px 32px rgba(31,35,41,.14) ← 抬升（层级）
入场：opacity 0→1 + translateY(6px)→0，180ms ease-out
出场：120ms 淡出（更快，减少等待感）
只动 opacity / transform，不碰 width/height/margin（避免重排）
@media (prefers-reduced-motion:reduce){ animation:none; transition:none }
```

## 四、输入框规范：去框线，改填充底

### 4.1 核心思路

白底 + 灰框 = 靠描边界定范围。改成**浅填充底 + 透明边框** = 靠底色块界定范围，
focus 时底色转白并浮出柔光。这样在白色卡片上不再有「一堆框线」，视觉安静。

```
静止：background:#f2f3f5（= --surface-2）  border:1px solid transparent
hover：background:#eceef1（比静止深一档）   ← 鼠标动线有反馈
focus：background:#fff                      ← 底色转白 = 「被激活」
       border-color:#dbe6fb（极浅蓝，对底 1.12，不抢）
       box-shadow:0 0 0 3px rgba(51,112,255,.12)  ← 柔光，非硬边
错误：background:#fff5f4
       border-color:#f0cdc9（--bad-line 同族）
       + 字段旁就地文案（颜色不能是唯一信号）
禁用：background:#f7f8f9  color:#a8adb5  cursor:not-allowed
```

### 4.2 为什么 focus 不用原来的 2px 深蓝 outline

原 `outline:2px solid #1d5fd6` 对白 5.74，在浅灰底上是一圈**高对比硬边**，
正是要避免的「强对比框线」。改为：底色变化 + 3px 低透明度柔光。

**但不能牺牲可访问性**：柔光半径 3px、透明度 .12 在浅底上仍可辨，
且底色由灰转白本身就是第二重信号（不只靠颜色）。
对 `prefers-reduced-motion` 无影响（不加动画）。

### 4.3 尺寸与一致性

| 项 | 值 | 说明 |
|---|---|---|
| 高度 | `padding:7px 12px` → 约 34px | 沿用现值，不改行高 |
| 圆角 | `--r-ctl`（6px） | 与按钮一致 |
| 字号 | 14px | 不变 |
| `select` | 同一套底/边 | 原生箭头保留（可访问性），只改底与边 |
| `textarea` | 同上 + `line-height:1.7` | 多行要松一点 |
| 搜索框/筛选框 | 自动继承 | 都在 `input` 选择器覆盖范围 |

### 4.4 会被影响的地方（改前必看）

`input,select,textarea` 是**全局选择器**，一改全站生效。已知依赖：

- `.dict-add input`（字典添加行）—— 有 `flex:1`，只受底/边影响
- `.jdform input/textarea/select`（岗位表单）——`width:100%`
- `.cand-drop` 收件人下拉里没有 input
- 顶部搜索框、看板页 `width:70px` 的跳页框 —— 只受底/边影响
- `#chatInput` 聊天输入 —— 需单独确认为**白色浮起**还是灰色填充

**聊天输入框单独处理**：它是页面的视觉焦点，且外面有自己的容器边框，
不跟随全局改填充底（否则会出现「灰底套在框里」的双层感）。

## 六、验收判据

改完必须逐条验，**判据要两边都验**（改前应失败、改后应通过）：

### 6.1 结构判据（读源码 / 读产物）

```
□ .sheet 容器是 overflow:hidden 而非 auto
□ #mBody 独立 overflow-y:auto 且 min-height:0
□ 存在 .sheet--sm / --md / --lg / --xl 四档
□ 存在 @media (max-width:600px) 的 bottom sheet 分支
□ 存在 prefers-reduced-motion 分支
□ input 的 border 不是 1px solid var(--line)
```

### 6.2 无障碍判据（浏览器实测）

```
□ 打开弹窗后 document.activeElement 在 #modal 内
□ 连按 Tab N 次（N > 容器内可聚焦数）后 activeElement 仍在 #modal 内
□ 按 Esc 后 #modal 不带 .on
□ data-lock="1" 时按 Esc 与点遮罩都**不**关闭
□ 关闭后 activeElement === 打开前的触发元素
□ #modal 有 role="dialog" / aria-modal="true" / aria-labelledby 指向存在元素
□ 关闭按钮有 aria-label
```

### 6.3 视觉判据（截图）

```
□ 白色卡片上的输入框看不到「灰色方框」，看到的是浅灰底块
□ 聚焦时是柔光晕 + 白底，不是 2px 深蓝圈
□ 弹窗没有 1px 边框，有阴影层次
□ 遮罩比改前浅，能看穿背景轮廓
```

### 6.4 防回归

```
□ python check_ui_js.py 通过（防白屏：_PAGE 是非 raw 三引号，JS 正则裸 \n 会被转义）
□ 六个业务流仍可用：导入 / 上传 / 分析 / 批量重跑 / 发信 / 档案详情
□ 弹窗链（progressModal → resultModal / chain 原地切换）不破
```

## 七、一句话总结

> 弹窗从「16 处随便用」收敛为「只留必须阻断的」，容器去掉边框与硬遮罩改用阴影分级，
> 输入框去掉灰框线改用浅填充底 + 柔光聚焦；同时把 22 处调用共用的 `#modal`
> 补齐 `role/aria/Esc/焦点陷阱/焦点归还` —— 这些是零视觉成本、纯可用性收益的改动。

### 8.3 实施时踩到的坑（都会复发，记下来）

1. **`var(--z)` 在 v2 不存在** —— v2 没有 `body{zoom}`，我照搬旧版的
   `calc(88vh / var(--z))` → 变量未定义 → **整条 `max-height` 声明在计算值阶段失效** →
   落回 `none` → 长内容把弹窗撑出屏幕。v2 直接用 `88vh`。
2. **`let` 的暂时性死区** —— `openModal` 定义在 2700 行，而 `resultModal`（1100 行）
   就引用它。函数声明会 hoisting，但 `let` 变量在声明前被读会 `ReferenceError`
   （本项目踩过同款：`__ingesting` 整页白屏）。三个状态量全改 `var`。
3. **共用 DOM 元素不要改 id** —— 为了保住 `progStopBtn` 这个历史 id，我把它设到
   `dlgNo` 上，又在开窗时 `removeAttribute('id')`；结果**第二次打开弹窗时
   `getElementById('dlgNo')` 已经返回 null**，整条开窗链路抛 TypeError。
   正确做法：改那两处引用（`progStopBtn` → `dlgNo`），不动 id。
4. **两份 Esc 监听器会互相拆台** —— v2 原来已有一个全局 Esc 监听，我又加一个，
   一次 Esc 触发两次 `closeProgDlg`，两次各自递增关闭令牌，先发起的那次被判"过期"放弃，
   行为不可预测；而且旧那份无条件关，绕过门控锁。删掉旧的，只留一处。
5. **`askText` 返回 Promise，CDP `awaitPromise:true` 会永久挂住** —— 测试脚本必须 `void` 掉。
6. **headless 下 `:focus` 不匹配** —— 不打开 `Emulation.setFocusEmulationEnabled`，
   所有聚焦态判据都拿到未聚焦样式（假 FAIL）。
7. **`transparent` 被算成 `rgba(0, 0, 0, 0)`** —— 判"无可见边框"只认字面量 `transparent` 会误报。
8. **`outline-width` 在 `outline-style:none` 时仍是 3px** —— 判"有没有硬 outline"
   必须看 `outlineStyle`，看宽度会恒真。
9. **`.14s` 过渡会让 computedStyle 读到中间值** —— blur 后立刻量背景色会拿到 focus 态的白，
   focus 后立刻量会拿到静止态的灰。两边都要等过渡走完再断言。
10. **`white-space:pre-wrap` + 模板换行 = 正文前面一大段空白** —— 拼接 HTML 时不能留缩进换行。

## 九、返工记录：第一次改漏了"用户第一眼看的地方"（2026-10-26）

### 现象
改完打包后业务方反馈：**"看不出来你修改啥了"**。

### 根因
本次只改了 `.cinput input` / `.crow input` / `.dlg-input` —— 这些是**弹窗与档案表单里的字段**。
但用户打开页面第一眼看到的是**顶部工具栏**：

| 控件 | 实际选择器 | 第一版改了吗 |
|---|---|---|
| 顶部搜索框 | `.search` | ❌ 没改 |
| 学历/阶段/性别筛选 | `.sel` `.vsel` `.stagesel` | ❌ 没改 |
| 跳页框 | `.pgjump` | ❌ 没改 |
| 聊天输入 | `.chatinput textarea` | ❌ 没改 |
| 可编辑值 | `.cval .ced` | ❌ 没改 |
| 多行表单 | `.mrow input` | ❌ 没改 |
| 教育字段 | `.edu-field input` | ❌ 没改 |
| 面试单位 | `#madd_ivunit` | ❌ 没改 |
| 富文本编辑区 | `#mBody` `.richeditor` | ❌ 没改 |

**这十几种控件各自有独立的 border 定义，全都在用 `var(--line-2)`（#c9cdd4 强分隔线）。**
所以"去框线"这件事，第一版只做对了不到三成，而且全是用户不第一眼看的部分。

### 修法
不去逐个改 20 多条原规则（容易漏、也容易把按钮和浮层卷进来），
在样式表**末尾**用**完全相同的选择器**再声明一次 —— 同特异性下后出现者胜，
只覆盖 `border` 与 `background`，padding/height/font 全部沿用原值（不改几何）。

```css
.search,.sel,.vsel,.stagesel,.pgjump,.chatinput textarea,
.cval .ced,.mrow input,.mrow select,.edu-field input,.edu-field select,
#madd_ivunit{
  border:1px solid transparent;background:var(--field);
  transition:background-color .14s ease,border-color .14s ease}
```
hover → `--field-hover`；focus → 底色转白 + `--field-line` + 3px 柔光。

**富文本区例外**：`#mBody` / `.richeditor` 是"一张纸"，写东西的地方应该是**白底**，
灰底会让正文看起来像禁用态。它们只把 `--line-2` 强框线换成极浅的 `--line`，
边界还在但不抢视线。

### 教训
1. **改视觉前先问"用户第一眼看哪里"**，不是"这套样式定义在哪"。
   按代码结构去找会漏掉工具栏这种"分散定义 + 首屏必经"的控件。
2. **判据不能看源码里有没有旧声明**：旧规则仍在文件里，只是被后面的覆盖了。
   第一次写的判据（"页面里不该出现 `border:1px solid var(--line-2)`"）报 FAIL，
   但实际样式是对的 —— 判据错了，不是代码错了。**唯一可信的是浏览器 computedStyle。**
3. **页面上没有的控件用注入法量**：CSS 规则对任何匹配元素都生效，
   注入一个同结构节点就能验，不必等"碰巧打开那个页面"。
   不这么做只能验到首屏恰好存在的 3 个，其余 9 类全靠猜。

### 验收
`tools/_ui_inputs_check.js` —— 12 类输入控件逐个量 computedStyle：**24/24**
（每类两项：无可见边框 + 填充底 #f2f3f5）。
